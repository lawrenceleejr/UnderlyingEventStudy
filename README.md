# UnderlyingEventStudy

**Can the soft underlying event predict the longitudinal boost of the hard scatter?**

The longitudinal boost of a hard scatter is fixed by the colliding partons'
momentum fractions `x1, x2` (boost rapidity `y = ½ ln(x1/x2)`). The beam remnants
and the soft underlying event (UE) that accompany every collision are
kinematically tied to `x1, x2` (Sjöstrand–Skands beam-remnant model,
[hep-ph/0402078](https://arxiv.org/abs/hep-ph/0402078); forward-energy ↔ beam-x,
[ALICE 2107.10757](https://arxiv.org/abs/2107.10757)). This project tests, with a
machine-learning regressor, whether the **soft particles alone** encode the boost
of the Z in `Z→μμ` events — the Z boost is measured from the two muons, and the
network sees only the *non-muon* soft particles.

This is, to our knowledge, a novel "inverse" use of the underlying event: prior
work regresses the *MPI count* from soft observables
([Ortiz et al. 2020](https://arxiv.org/abs/2004.03800)) or `x1,x2` from the
*hard* final state ([Sborlini et al. 2112.05043](https://arxiv.org/abs/2112.05043)),
but not the hard-scatter longitudinal boost from the soft event.

## Two ways to run

### 1. Simulation (runs anywhere — Pythia8)
Truth-level `Z→μμ` with full soft-particle information and no pileup: the cleanest
test of whether the information is *there*.

**Train on your machine in one line** (auto-uses Apple Metal / MPS on an M-series
Mac, CUDA on NVIDIA, otherwise CPU — no flags needed). A compact 35k-event dataset (`data/skim/pythia_demo.parquet`) is committed, so this
trains immediately; the full 76k sample is regenerated by `sim/generate.py`:

```bash
bash train.sh                      # = pip install + EFN+Transformer on the best device
```

On a Mac Studio M2 this runs on the GPU via PyTorch MPS automatically. To force a
backend: `python -m src.evaluate --parquet data/skim/pythia.parquet --device mps`.

Full manual flow (regenerate data, ablation):

```bash
pip install -r requirements.txt
bash sim/build_pythia.sh                       # build Pythia8 + python bindings -> /opt
export PYTHONPATH=/opt/pythia8312/lib:$PWD
python -m sim.generate --nevents 220000 --out data/skim/pythia.parquet
python -m src.evaluate --parquet data/skim/pythia.parquet --models efn transformer --device auto
python -m src.ablation --parquet data/skim/pythia.parquet      # central vs forward dissection
```

### 2. Real CMS Open Data (needs Docker + internet + ~100 GB disk)
The diffuse soft tracks live only in MiniAOD's `packedPFCandidates`, which require
CMSSW to read. `opendata/run.sh` does everything: pull the CMSSW image, stream the
DoubleMuon Run2016G MiniAOD ([record 30505](https://opendata.cern.ch/record/30505)),
flatten muons + **all** PF candidates (+`lostTracks`) with the self-contained
`PFNanoLite` EDAnalyzer (no GlobalTag/Frontier needed), then skim + train/evaluate.

```bash
./opendata/run.sh 5            # process 5 MiniAOD files
# -> results/REPORT_opendata.md
```

> Note: the convenient flat open-data PFNano ([record 31305](https://opendata.cern.ch/record/31305))
> stores only *jet-constituent* PF candidates — the diffuse soft UE is absent —
> which is why we produce `_allPF` content ourselves with `PFNanoLite`.

## Pipeline (shared by both paths)

| stage | file | what |
|---|---|---|
| config | `src/config.py` | records, selection cuts, soft-particle definition |
| I/O | `src/io.py` | list/stream/download Open Data over HTTPS (no xrootd) |
| selection | `src/select.py` | `Z→μμ` selection, targets `y_Z`, `pz`, `β_z` |
| soft particles | `src/softparticles.py` | muon removal, soft/UE selection, PV+PUPPI pileup suppression |
| skim | `src/skim.py` | `make_records` → per-event Parquet (shared schema) |
| simulation | `sim/generate.py` | Pythia8 `Z→μμ` → same Parquet schema |
| dataset | `src/dataset.py` | Parquet → padded tensors, splits, standardization, particle filters |
| models | `src/models/efn.py`, `transformer.py` | Energy Flow Network (Deep Sets) and Particle Transformer |
| train/eval | `src/train.py`, `src/evaluate.py` | Huber multi-output training; metrics, plots, report |
| baselines | `src/baselines.py` | mean / linear / GBDT on UE summary observables |
| ablation | `src/ablation.py` | where the boost info lives: central vs forward |

Targets: `y_Z` (primary — the Lorentz boost rapidity), `pz`, `β_z`.
Per-particle inputs are longitudinal-info-safe (each particle's own η, log pₜ,
charge, PUPPI, and azimuth *relative to the Z*; never the muon η/pz).
